# DEMO.md — showing mycc to someone who does not write code

Run `demo.bat`. That's the whole thing. This file is what you say while it runs.

Two rules, both learned the hard way:

1. **Never let them read the terminal for longer than one screen.** Every scene
   ends with a sentence, not with output.
2. **Never say a number you have not verified.** Every figure below was produced
   by the command next to it; `demo\expected.txt` is the real transcript.

---

## The 60-second version

Say this once, then run scene 2 and stop:

> "A compiler translates things people can read into things machines can read.
> Almost all of them are millions of lines and nobody can look inside. Mine is
> six and a half thousand lines and every part of it is yours to inspect. It
> compiles C — a small but real subset — to actual assembly. Ask it something."

Then let them type their name. When it prints back, that's the demo. Nothing
that follows beats it for a non-technical audience.

## The three-minute version (scenes 1–3)

| Time | Command | What to say |
|---|---|---|
| 0:00 | — | "Two weeks ago this compiler's entire output was a number in a register. Nobody could see it. Today it can print." |
| 0:20 | `demo.bat` scene 1 | "That text came from `printf` — inside the C library. To use it, my compiler had to obey the same calling rules Microsoft's compiler obeys." |
| 0:50 | scene 2 | "Your turn. Type your name." *(let them)* "A local array, a library call, three strings, and the real ABI." |
| 1:40 | scene 3 | "Same program, compiled twice. The right-hand one has the optimizer off. I haven't run either." *(run both)* "Both returned 118. The optimizer removed work, not behaviour." |
| 2:30 | scene 5 | "33 programs it must accept, 41 mistakes it must reject, and every answer checked against the compiler the world actually uses." |

Stop there. If they ask "but is it really yours", go to scene 4.

## The five-minute version (all scenes)

Add scene 4 — the answer to the only question that matters:

> "A fair question. So I asked the program itself."

`mycc --version` prints what it is. Then `--sign` stamps one string into the
program's data, and `strings` finds it inside the finished `.exe`:

```
generated by mycc (C-subset compiler) + github.com/AkshatJski/C-Compiler-Mini-Project
```

> "gcc assembled that file. But mycc wrote that string into it. My compiler is a
> few hundred kilobytes; gcc is millions of lines. It cannot secretly be gcc."

If you only get one more minute, spend it here.

## Questions you will actually be asked

| Question | Answer |
|---|---|
| "Is this just gcc with extra steps?" | gcc is the *assembler* here — the copy-paster of instructions into a binary. mycc writes those instructions. Scene 4 proves the binary carries mycc's stamp. |
| "Is it as good as a real compiler?" | No, and it says so. No optimizer beyond folding and dead branches; no floats; no preprocessor; structs are never passed by value. `ROADMAP.md` lists exactly where it stops. |
| "How long did it take?" | *(answer honestly — the commit history is public and matches)* |
| "Who uses it?" | Nobody. It's a teaching artefact — a glass box, not a product. That's the point. |
| "Could it compile a real program?" | It compiles programs of a few hundred lines that use pointers, arrays, structs, loops and `printf`. It cannot compile `#include <stdio.h>` — mycc has no preprocessor; the built-ins replace it. |
| "Did you have to write the CPU part too?" | No — x86-64 is a fixed language, and I emit it as text. That's why two different machines can both run the same program. |
| "What happens if I write garbage?" | It refuses, with a message that points at the line and column. Try it live — that's a good moment, not a bad one. |

## If something breaks

1. **No output at all** — `mycc.exe` missing: run `build.bat` first.
2. **`gcc: not found`** — the script already probes `C:\msys64\ucrt64\bin` and
   `C:\w64devkit\bin`; set `CC` to your gcc if it lives elsewhere.
3. **Scene 2 prints `Hello, !`** — you are running the script with piped input
   instead of a real terminal; the prompt consumed the name. Run it by hand.
4. **Anything else** — stop talking, open `demo\expected.txt`, and read it out.
   It is the real transcript, not a mock-up. Nobody needs to see the failure.

---

## What not to do

- Do not open `--dump-tokens` or `--dump-ast` for this audience. Save them for
  the one person who asks a technical question — then they are gold.
- Do not read assembly aloud.
- Do not explain the calling convention. Say "the same rules Microsoft's
  compiler obeys" and move on.
- Do not apologise for what it cannot do. State the boundary once, plainly, and
  it reads as confidence.
